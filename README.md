VmaxBuilder is an orchestrator-driven Python toolbox for turning model, protein, Kcat,
and allocation inputs into condition-specific reaction capacity estimates for genome-scale
metabolic models.

## What it does

The pipeline runs in a fixed stage order:

1. Model preprocessing.
2. Protein preprocessing.
3. Allocation.
4. Kcat estimation and resolution.
5. Vmax calculation.

The orchestrator selects the implementation for each stage, loads inputs, runs the
stages in order, and saves outputs, artifacts, diagnostics, and metadata.

## Quick start

```console
uv venv
source .venv/bin/activate
uv sync
```

If you want the UniKP extras used by the Kcat workflow:

```console
uv sync --extra unikp
```

The allocation and Vmax stages currently rely on Gurobi through `gurobipy`. Install
Gurobi and activate a valid license before running those stages.

## How the runtime works

The user-facing flow is:

1. Build `RunConfig`.
2. Build `StageLoading` with per-stage input locations.
3. Create `Orchestrator`.
4. Select concrete implementations with the stage setter methods.
5. Run the orchestrator.

Example skeleton:

```python
from pathlib import Path

from VmaxBuilder.base.configs import RunConfig, StageLoading, StageLoadingInfo
from VmaxBuilder.base.orchestrator import Orchestrator
from VmaxBuilder.stages.Kcat.UniKPMainSubstrate.implementation import UniKPMainSubstrateImplementation
from VmaxBuilder.stages.Vmax.default.reaction_resolving import DefaultVmaxReactionResolving
from VmaxBuilder.stages.allocation.FairAllocation.implementation import FairAllocationImplementation
from VmaxBuilder.stages.model.default.implementation import DefaultIrreversibleModelImplementation
from VmaxBuilder.stages.protein.MvalueTrimmingExpressionPTR.implementation import MvalueTrimmingExpressionPTRImplementation

run_config = RunConfig(
    output_dir=Path("data/results"),
    run_name="demo_run",
    print_level="INFO",
)

stage_loading = StageLoading(
    model_loading_info=StageLoadingInfo(stage_name="model", directories=[Path("data/inputs/model")]),
    protein_loading_info=StageLoadingInfo(stage_name="protein", directories=[Path("data/inputs/protein")]),
    allocation_loading_info=StageLoadingInfo(stage_name="allocation", directories=[Path("data/inputs/allocation")]),
    Vmax_loading_info=StageLoadingInfo(stage_name="Vmax", directories=[Path("data/inputs/Vmax")]),
    Kcat_loading_info=StageLoadingInfo(stage_name="Kcat", directories=[Path("data/inputs/Kcat")]),
)

orchestrator = Orchestrator(stage_implementations=stage_loading, run_config=run_config)
orchestrator.set_model_implementation(DefaultIrreversibleModelImplementation)
orchestrator.set_protein_implementation(MvalueTrimmingExpressionPTRImplementation)
orchestrator.set_allocation_implementation(FairAllocationImplementation)
orchestrator.set_Kcat_implementation(UniKPMainSubstrateImplementation)
orchestrator.set_Vmax_implementation(DefaultVmaxReactionResolving)
orchestrator.run()
```

## Inspecting configuration and output

Use the orchestrator to inspect the active config and control logging:

```python
print(orchestrator.return_config("run"))
print(orchestrator.return_config("allocation"))
orchestrator.set_print_level("DEBUG")
```

Outputs are written under `output_dir / run_name` in these folders:

- `outputs`
- `artifacts`
- `diagnostics`
- `metadata`

## Development notes

- The codebase targets Python 3.11.
- Documentation is built with Sphinx from `docs/source/`.
- UniKP is optional and only needed for Kcat workflows that use it.
- The modular pipeline is intended to be extended by adding new implementations, not by forking existing ones.
